# kiro-trust 0.3.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add bounded model inspection, manual model availability discovery,
offline diagnostics, precise retry classification, local usage summaries, and
evidence-gated history images on top of the safe refresh-token chain.

**Architecture:** The compiled protocol catalog remains the only source for
inference routing. A manual discovery client uses a fixed destination and one
ordinary `TokenSource` across all pages, doctor uses offline readers plus an
optional unauthenticated loopback health probe, and the server owns a bounded
in-memory usage aggregate tied to response-body lifetime. Shared-file slices
run sequentially and receive independent review before integration.

**Tech Stack:** Rust 1.98.1, edition 2024, clap 4, axum 0.8, reqwest 0.13 in
`kiro-trust-net` only, serde/serde_json, secrecy 0.10, tokio 1.53, httpdate
1.0.3.

**Spec:** The [0.3.0 design](../specs/kiro-trust-0.3.0-design.md) defines the approved changes.
Executors must also read and update `docs/specs/kiro-trust-design.md`, which
remains authoritative.

## Global Constraints

- Read `AGENTS.md`, `docs/specs/kiro-trust-design.md`, and the 0.3.0 design
  before each slice.
- Toolchain stays `1.98.1`; `edition` and `rust-version` stay `2024` and
  `1.98.1`.
- Dependency direction stays `kiro-trust` to `kiro-trust-kiro` to
  `kiro-trust-net` and `kiro-trust-protocol`, with `kiro-trust-auth` to
  `kiro-trust-net`.
- `reqwest` stays in `kiro-trust-net` only. Every production host is selected
  by `Destination`; no public URL, host string, or base-URL override is added.
- `kiro-trust-protocol` gains no `tokio`, `reqwest`, or `rusqlite`.
- The database remains read-only and limited to `auth_kv` and `state`.
- The exact six production `expose_secret()` sites remain unchanged.
- New inspection output never contains a token, profile ARN, account id,
  header value, body, prompt, tool data, conversation id, or pagination token.
  Preserve the existing `env` and `exec` token handoff contracts. Log only the
  fields allowed by spec 6.4.
- Unknown inference models remain a 400. Discovery never enables or routes a
  model and never loads during `serve`, `audit`, `doctor`, or `GET /v1/models`.
- Local listener addresses remain loopback-only. All routes except `/health`
  require the local token.
- Text frames remain incremental with no overlap removal.
- Update the source-of-truth spec first and in the same commit as each behavior
  change. Remove closed backlog rows in that commit.
- Update `AGENTS.md`, `audit`, its synthetic fixture, and security documentation
  in the discovery and doctor commits that change their guarantees.
- Cap offline tests with `cargo test --locked --workspace -- --test-threads=6`.
- Do not run runtime live tests until the documented allowance resets.
- A forced OIDC refresh test requires both `KIRO_TRUST_LIVE=1` and
  `KIRO_TRUST_LIVE_REFRESH=1`.
- Release and feature builds select `-p kiro-trust`, never a workspace build.
- Do not publish to crates.io. Version 0.3.0 needs a separate owner approval.

## Execution order and ownership

The primary integrator owns planning, cherry-picks or merges, full verification,
Git operations, and release preparation. Each implementation worker uses a
separate worktree and owns only the paths listed for its task. The tasks run in
order because the main spec, manifests, CLI dispatch, and server state overlap.
After each task passes its focused tests, a fresh Sol reviewer checks the diff.
A design or review worker must not implement that slice.

| Order | Slice | Owned implementation paths |
| --- | --- | --- |
| Gate | Refresh-chain baseline | Existing auth branch and its tests; no 0.3.0 worker reimplements it |
| 1 | Compiled model commands | protocol catalog, CLI config/dispatch, new `models_cmd.rs`, model command tests, main spec |
| 2 | Manual discovery | net destination/client, auth profile metadata, kiro discovery module, CLI discovery branch, new tests, NOTICE copies, main spec |
| 3 | Doctor | net loopback probe, CLI config/dispatch, new `doctor.rs`, new tests, main spec |
| 4 | Retry classification | kiro client/error, server error/messages, retry tests, fixture data, main spec |
| 5 | Usage summary | protocol response translator, kiro error attempts, server state/messages/new usage module, server tests, main spec |
| 6 | History images | protocol history/content/catalog, image and live tests, main spec |
| 7 | Version and release readiness | manifests, lockfile, changelog/readme/security/release docs, package fixtures and gates |

Do not assign two active workers files from the same row or overlapping rows.
Integrate and review one row before the next worker starts.

The live gate in Task 2 blocks only discovery integration. If account access is
not proved, start Tasks 3 through 7 from the reviewed Task 1 commit and leave
Task 2 on its worktree. The fixture gate in Task 4 blocks only the
`allowance_exhausted` refinement; the reviewed Retry-After and transient
classification work may integrate without it.

Task 6 also gates only history forwarding. On live unavailability, retain the
reviewed Task 5 commit and keep `history_images_forwarded = false`; use that
commit as Task 7's base. On structural rejection, make a reviewed spec-only
commit recording the result, then use that commit as Task 7's base. On success,
use the reviewed history implementation commit. Task 7 documents only integrated
features: a deferred discovery slice has no discover subcommand, no new catalog
destination, and audit still reports discovery disabled.
